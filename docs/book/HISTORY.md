# The Cella Journey

> A record of how an idea became a database.

## 1. Before Cella

Cella did not begin with a roadmap, an architecture diagram, or a
database design.

It began with curiosity.

I was watching the YouTube podcast:

**"How Dukaan moved out of Cloud and on to Bare Metal w/ Subhash | Ep 5"**

During the conversation, I heard that the interviewer was building his
own database.

That idea stayed with me.

I had already worked with databases while building applications, but
I realized that I mostly knew databases from the perspective of a
developer who uses them.

I wanted to know what was happening underneath.

How is data actually stored?

How does a database read it?

How do files, memory, the operating system, system calls, indexes,
transactions, and all the other pieces come together?

And eventually, a very simple thought came to me:

**Why don't I build one myself?**

I didn't know exactly how difficult it would be.

I didn't have the complete architecture.

I didn't know everything I would need to learn.

But I knew that I wanted to try.

## 3. SomaDB

When I first decided to build the database, I called it **SomaDB**.

"Soma" is the name of a friend of mine.

At that point, the project was still just an idea. I liked the name
because it had a personal meaning, even though it did not describe
what the database actually represented.

SomaDB was the first identity of the project.

It was the name under which the idea was born.

## 4. Why SomaDB Became Cella

As I thought more seriously about the project, I wanted the name to
have some connection with what I was actually building.

I came across the word **Cella**, a Latin word associated with a chamber,
room, or storeroom — a place where things are kept.

That connection felt right.

A database is fundamentally a system for storing and organizing
information.

SomaDB was personal.

Cella felt like a name for the system itself.

So I decided to rename the project.

**SomaDB became Cella.**

This was the first small decision that gave the project a stronger
identity.

## 5. The Beginning of Cella

I am not building Cella because I think I can replace PostgreSQL.

I am building it because I genuinely want to build a database.

I want to understand how a database works from the inside.

I want to understand how the database connects with the operating
system, memory, files, storage, system calls, concurrency, networking,
and all the other systems that make it possible.

There is also something personal behind this project.

I follow engineers who build difficult things that eventually make
other people's lives easier. Seeing what they build inspires me.

I want to experience that process myself.

Not by copying what someone else has built, but by building something
in my own way, with my own identity.

And honestly, I want to have fun doing it.

## 5. What I Want Cella to Become

At the beginning, Cella was simply an idea: build a database to
understand databases.

But I don't want the project to remain a toy implementation.

My long-term goal is for Cella to become a lightweight relational
database that people can actually use to build small applications
and projects.

I want to eventually give Cella to my friends and ask them to build
real projects using it.

If someone can download Cella, create a database, create tables, store
data, query it, use transactions, and build an application around it,
then Cella has become something real.

At the same time, I want the entire process of building Cella to be
transparent.

Someone should be able to come to this repository years later and
learn how a database can be built from scratch.

They should be able to see the concepts, experiments, design decisions,
implementation, failures, benchmarks, and lessons that led to the
final system.

I want Cella to be both a database people can use and a project people
can learn from.
